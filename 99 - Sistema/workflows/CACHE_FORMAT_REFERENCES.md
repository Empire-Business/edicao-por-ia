# Referências do Cortez sob demanda

As receitas, guias, índices, análises e hashes fazem parte da atualização pequena de código. Os vídeos e demais mídias da biblioteca aprovada ficam no mesmo repositório público e são baixados somente para o formato solicitado. O Vimeo exibe os exemplos no painel; não é a fonte de arquivos para a edição e não exige a chave do autor nas instalações dos usuários.

Ao preparar um trabalho, `format_fidelity.snapshot` chama `reference_cache.ensure` para buscar apenas as referências escolhidas. A cópia é fixada no commit registrado pelo atualizador, verificada por SHA-256 e tamanho e guardada no caminho relativo original em `examples/reference-library/Fxx`. Uma instalação Git nova resolve a main pública e também exige o hash do índice local. Se esse índice antigo não corresponder à origem atual, atualizar o código antes; nunca substituir o exemplo por outro ou ignorar o hash.

A IA pode antecipar o cache de um formato com `tools/reference_cache.py --format Fxx`. Não apresentar comandos para leigos. Falha de rede deixa a edição pendente; não renderizar sem a referência exigida. Arquivos já disponíveis não são baixados novamente. Arquivos modificados não são sobrescritos nem apagados. Depois do cache, todos os materiais usados continuam dentro da pasta e viajam com ela. Nunca buscar a biblioteca toda para uma atualização de código.

Para publicar exemplos no Vimeo, usar `tools/vimeo_publish.py`: prévia primeiro; `--apply` somente com autorização atual do autor para esses uploads. O selecionador aceita apenas referências públicas indexadas e selecionadas em `publication.json`, inclusive as variações. Chave, links de upload e recibos de retomada ficam privados em `.factory/`, fora do manifesto. Usar a pasta Cortez, conferir cota existente, guardar cada URI antes de enviar blocos TUS e reutilizar o recibo/hash para evitar duplicações. Não contratar plano, editar outros vídeos da conta nem distribuir credenciais. Só ativar no catálogo vídeos cujo processamento terminou.
